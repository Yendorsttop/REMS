# RED-001 Constitutional Traceability

System-security evidence is intentionally outside RED-001 business-audit ownership. ADR 0007, the
additive migration and bootstrap, and authentication tests trace that boundary without assigning an
unauthenticated event to an executive identity.

| Constitutional responsibility                | Authoritative implementation                                                                               | Executable evidence                                                           |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Executive identities and lifecycle           | `ExecutiveIdentity`, value objects, `Red001Service`, Prisma repository                                     | domain, service, and database integration tests                               |
| Organizational hierarchy, departments, teams | `OrganizationUnit`, `createUnit`, Prisma repository                                                        | service, migration, and database integration tests                            |
| Memberships and reporting relationships      | `Membership`, `assignMembership`, restrictive foreign keys                                                 | service, schema, integration, and deletion tests                              |
| Role and permission assignments              | `PermissionAssignment`, Prisma authorization adapter                                                       | authorization service and database integration tests                          |
| Business authorization context               | `AuthorizationContext`, `AuthorizationPort`                                                                | denial-path tests                                                             |
| Identity-based participation                 | repository ports and membership model                                                                      | architecture-boundary tests                                                   |
| Decision audit                               | `AuditEventPort`, Prisma insert adapter, shared command transaction, PostgreSQL append-only runtime grants | emitted-event, restricted-role privilege, and transaction rollback assertions |

RED-001 is the exclusive authoritative owner of this vocabulary and policy. API contracts may project RED-001 data but do not acquire authority. Synthetic fixtures are clearly named and convey no real organizational facts.

Database integration tests execute when `DATABASE_URL` targets a migrated PostgreSQL test database. FIP-005C security tests additionally connect as the actual `rems_application` and `rems_audit_reader` roles to verify append/read permissions and rejected audit mutation. CI evidence does not prove production provisioning, exclude privileged administrative alteration, or establish operational certification.

## FIP-005D

| Policy                         | Implementation / evidence                                                   |
| ------------------------------ | --------------------------------------------------------------------------- |
| Immutable external account key | `ExternalIdentityLink` unique `(issuer, subject)`                           |
| Standards verification         | Nest guard and JOSE remote JWKS verifier                                    |
| RED-001-only authority         | Active link resolver plus persisted permission adapter                      |
| Default denial                 | Guard rejects verification failures, missing links, and inactive identities |
| Rotation and adverse tokens    | Controlled local issuer tests                                               |
| Audit limitation               | ADR 0005 system-security evidence proposal                                  |

External identity link resolution is implemented through application-role `SELECT`. FIP-005E administration is isolated in the controlled CLI and persistence role below.

## FIP-005E

| Policy                         | Implementation / evidence                                                                      |
| ------------------------------ | ---------------------------------------------------------------------------------------------- |
| One-time Founder ceremony      | Non-HTTP `founder-identity.mjs` with exact confirmation and fail-closed state checks           |
| Atomic authority establishment | One Prisma transaction creates identity, root membership, exact link, and audit event          |
| Founder-authorized lifecycle   | Verified issuer/subject resolves an active persisted Founder before five link commands         |
| Last-link protection           | Suspend/remove refuse the final usable Founder link; replacement is transactional              |
| Persistence separation         | One-time `rems_founder_bootstrap`, ongoing `rems_identity_admin`, and unchanged runtime grants |
| Evidence limits                | ADR 0006 and certification evidence exclude production ceremony and recovery claims            |

## FIP-005G operational trace

ADR 0008 preserves RED-001 authority while separating application runtime from migrations, identity administration, security reading, backup, and restoration. Backup is read-only evidence preservation, never a competing executive or organizational authority. CI verifies representative RED-001 and audit restoration; this is repository evidence and not operational certification.

## FIP-005H staging trace

| Boundary                      | Staging declaration / verification                                                                          |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Exclusive executive authority | Auth0 authenticates only; exact issuer/subject is linked through RED-001 controlled administration          |
| Runtime persistence           | API alone receives externally injected `rems_application`; web receives no database credential              |
| Schema authority              | Normally suspended release executor alone receives `rems_migration_owner`                                   |
| Ceremony authority            | Synthetic staging ceremony uses an isolated process and immediate independently verified `NOLOGIN` lockdown |
| Audit/evidence separation     | Business audit retains an authenticated RED-001 actor; pre-auth security evidence never fabricates one      |
| Recovery                      | Backup/restoration preserves RED-001 data but does not acquire organizational or executive authority        |

ADR 0009 and the controlled runbook preserve these boundaries across Render, Auth0, Better Stack,
Cloudflare staging DNS, and external backup custody. Provider configuration and passing template gates
cannot confer RED-001 roles or constitute certification.
