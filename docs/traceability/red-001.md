# RED-001 Constitutional Traceability

| Constitutional responsibility                | Authoritative implementation                                                                               | Executable evidence                                                           |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Executive identities and lifecycle           | `ExecutiveIdentity`, value objects, `Red001Service`, Prisma repository                                     | domain, service, and database integration tests                               |
| Organizational hierarchy, departments, teams | `OrganizationUnit`, `createUnit`, Prisma repository                                                        | service, migration, and database integration tests                            |
| Memberships and reporting relationships      | `Membership`, `assignMembership`, restrictive foreign keys                                                 | service, schema, integration, and deletion tests                              |
| Role and permission assignments              | `PermissionAssignment`, Prisma authorization adapter                                                       | authorization service and database integration tests                          |
| Business authorization context               | `AuthorizationContext`, `AuthorizationPort`                                                                | denial-path tests                                                             |
| Identity-based participation                 | repository ports and membership model                                                                      | architecture-boundary tests                                                   |
| Decision audit                               | `AuditEventPort`, Prisma insert adapter, shared command transaction, PostgreSQL append-only runtime grants | emitted-event, restricted-role privilege, and transaction rollback assertions |

RED-001 is the exclusive authoritative owner of this vocabulary and policy. API contracts may project RED-001 data but do not acquire authority. Synthetic fixtures are clearly named and convey no real organizational facts.

Database integration tests execute when `DATABASE_URL` targets a migrated PostgreSQL test database. FIP-005C security tests additionally connect as the actual `rems_application` and `rems_audit_reader` roles to verify append/read permissions and rejected audit mutation. CI evidence does not prove production provisioning, exclude privileged administrative alteration, or establish operational certification.

## FIP-005D

| Policy                         | Implementation / evidence                                                   |
| ------------------------------ | --------------------------------------------------------------------------- |
| Immutable external account key | `ExternalIdentityLink` unique `(issuer, subject)`                           |
| Standards verification         | Nest guard and JOSE remote JWKS verifier                                    |
| RED-001-only authority         | Active link resolver plus persisted permission adapter                      |
| Default denial                 | Guard rejects verification failures, missing links, and inactive identities |
| Rotation and adverse tokens    | Controlled local issuer tests                                               |
| Audit limitation               | ADR 0005 system-security evidence proposal                                  |

External identity link resolution is implemented through application-role `SELECT`. Administration is intentionally absent. Future lifecycle changes require separately approved, actor-authorized RED-001 commands, audit events, and an appropriate controlled persistence authority.
